Dissecting & Rebuilding the DataOn Company Profile

A practice project cloning an enterprise HRIS website to understand the structure and design patterns of a B2B SaaS company profile.

Background

DataOn is an HRIS (Human Resource Information System) provider with an enterprise B2B-style company profile website: many sections, complex navigation, and information-dense content. This project was built as practice in replicating that structure from scratch, without access to the original source code.

Challenge

The original website uses a mega menu with many product sub-categories, a tight feature grid, and dynamically arranged client logos and testimonials. The main challenge was rebuilding this layout manually while keeping proportions and spacing between elements consistent across different screen sizes.

Process

  1. Visual audit of the original page

    Breaking the page down into sections: hero, products, features, clients, testimonials, footer.

  2. Building a semantic HTML structure

    Creating the skeleton of each section so it is easy to style and maintain.

  3. Styling & reusable components

    Creating cards, buttons, and grids that can be reused across several sections.

  4. Responsive testing

    Adjusting the mega menu and feature grid so they stay neat on mobile screens.

Solution

The end result is a company profile with a section structure that follows the original pattern: a hero with a clear CTA, a product feature showcase, client logos as social proof, customer testimonials, and a complete footer with navigation.

Hero + CTA Product mega menu Feature grid Client logos Testimonials

Results & Learnings

This project trained my ability to read the structure of a complex enterprise UI and translate it into clean, modular code, while also helping me understand how B2B SaaS companies build a narrative of trust (trust signals) on their main pages.

Reflection

The biggest challenge was not the styling, but keeping spacing consistent across so many sections. Breaking components into small parts from the start helped a lot with this.

Background

This app was built for simple draw needs, such as picking a giveaway winner or choosing a name at random from a list, in a way that is more engaging than a plain random number generator.

Challenge

The main challenge was the animation: the wheel has to look like it is truly spinning at random, stop smoothly on one segment, and still feel fair to every participant even when the number of names changes.

Process

  1. Researching the random logic

    The winner is picked at random first, then its index is mapped to the wheel's rotation angle so the animation always matches the winner.

  2. Designing dynamic segments

    The wheel is divided into colored segments with conic-gradient according to the number of names entered.

  3. Spin animation

    Using a CSS transition with easing so the spin feels natural and slows down at the end.

  4. Testing with different numbers of names

    Making sure the animation and labels stay neat for both a small and a large number of names.

Solution

Users enter a list of names, then press the spin button. The wheel spins with a convincing animation before stopping on one name, which is then shown as the winner.

Results

The app is used for simple draws and feels more lively than just showing a name instantly. The process of "waiting for the wheel to stop" adds excitement for those watching.

Reflection

The hardest part was making the animation easing feel "fair": not stopping too quickly, but not dragging on either. Tuning the duration and animation curve took several manual attempts.
